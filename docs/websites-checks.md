# Этап 3: сбор сайтов

Проверено 22 октября 2026 года настоящими запросами из Docker. Использовались
только публичные страницы и API без авторизации. Формы отклика не отправлялись,
Telegram-бот не запускался, рабочие данные не удалялись.

| Источник | Результат |
|---|---|
| К2 | 7 вакансий, полные описания 1970–3247 символов, 7 ссылок на форму |
| КРОК, опыт 0–1 год | 13 вакансий, полные описания 1094–1835 символов, 13 ссылок на форму |
| РТК ИТ | HTTP 401 от API; источник явно не подключён, вымышленные вакансии не возвращаются |

Число вакансий не равно числу подходящих возможностей: тематическая фильтрация
и проверка начального уровня относятся к этапу 4. Наличие формы не доказывает,
что компания принимает заявки. Проверка реальной отправки в Telegram — этап 6.

## К2

Сначала читается заданная карьерная страница. Из её настройки Tilda извлекаются
`recid` и `storepart`, используемые самим сайтом. Публичный каталог
`https://store.tildaapi.com/api/getproductslist/` возвращает JSON без токена.
Сборщик проходит `nextslice` и сверяет количество уникальных записей с `total`.
RSS на проверенной странице не объявлен; доступный публичный API используется
вместо прежнего sitemap.

Каждая вакансия читается полностью. Известные блоки Tilda дают заголовок,
занятость, обязанности, требования и условия, исключая меню и футер. Текст для
фильтра сохраняется полностью; только краткое описание обрезается до 500 символов.
Ссылка формы имеет вид URL вакансии + `#form`, если соответствующая форма присутствует.

Дата `lastmod` sitemap больше не выдаётся за дату публикации. Поля дат заполняются
только из явной разметки `JobPosting`. На всех семи проверенных страницах такой
разметки дат нет, поэтому даты оставлены неизвестными. Стажёр-аналитик SOC теперь
читается с полным описанием и не получает вымышленную дату из sitemap.

## КРОК

Старый параметр `_sft_expirience` в пользовательской ссылке не применяет фильтр
на текущем сайте. Сборщик читает публичный `select[name="EXPERIENCE"]`, находит
значение опции «0-1 год» и отправляет новый URL с этим параметром. Сервер должен
подтвердить выбранный фильтр через `option[selected]`.

Читается полный список `.jsVacanciesSorted .jsVacanciesListValues`, а не
ограниченная группированная выдача. Сейчас в нём 13 вакансий, включая стажировки
Linux, SOC и ЦОД, отсутствовавшие в старой выборке. Реальные ссылки `PAGEN_*`
поддерживаются, при переходе сохраняется фильтр опыта. Повтор содержимого
страницы и неизвестная пагинация дают ошибку вместо неполного результата.

Все карточки загружаются подробно — ограничения «только первые 15» больше нет.
Из `.vacancy-detail__content-main` берутся заголовок, теги опыта/занятости/города,
вводный текст и соседние секции обязанностей, требований и условий. Форме
соответствует якорь `#responseForm`. На 13 проверенных страницах дата публикации
не объявлена в `JobPosting`; она не выдумывается. RSS/API не объявлены на
проверенных страницах каталога, используется HTML конкретного шаблона сайта.

## РТК ИТ

`https://rtkit.ru/careers` отдаёт оболочку приложения. Публичный запрос
`POST https://rtkit.ru/api/v1/vacancies` с пустым JSON без авторизации вернул 401.
Попыток подставить ключ из JavaScript, войти в аккаунт или обойти ограничение нет.

Прежний парсер `vacanciesCollection()`/`eventsCollection()` удалён: это выключенные
демонстрационные коллекции, подтверждённые аудитом. Сборщик теперь сохраняет
понятную ошибку источника. Даже при будущем ответе API 200 данные не будут
автоматически приняты без проверки схемы и актуальности.

Если старая версия сохранила демонстрационные вакансии РТК ИТ в очереди, их
отправка блокируется для настроенных источников типа `rtkit_careers`. Строки
остаются в SQLite для последующего разбора. Эта узкая защита не исправляет
остальные известные проблемы повторной доставки — они остаются этапом 5.

## Полнота, состояние и ограничения

- Ошибка любой необходимой страницы отменяет весь сбор источника. Пустая выдача
  допустима только при явном нулевом результате API/сообщении сайта.
- HTTP 401/403/429, редиректы и страницы проверки доступа дают явную ошибку.
  Переходы на посторонние домены из каталога/пагинации запрещены.
- Запросы имеют тайм-аут и общую паузу минимум 2 секунды. GET и диагностический
  POST используют одну очередь пауз.
- По умолчанию `max_pages: 20`, `max_details: 150`. Эти положительные целые числа
  можно задать в элементе `websites` конфигурации. Превышение — ошибка, не обрезка.
- Неудачный сбор не помечает источник инициализированным. После успеха прежняя
  ошибка очищается. Первый успешный сбор нового сайта сохраняется без архива,
  даже после `/start`.
- Ключи источников, существующие таблицы и строки сохранены. ID вакансии остаётся
  slug из URL, а не Tilda UID. Если компания меняет URL/алиас, ID может измениться;
  межисточниковая дедупликация будет доработана на этапе 5.
- Не выполняются действия с формами, OCR и распознавание произвольных дат из
  текста. При отсутствии явной даты используется `None`, статус — `unknown`.
- Доступность и структура сайтов могут измениться. Для РТК ИТ сейчас нет
  подтверждённого публичного подключения; все 10 источников одновременно не работают.

## Проверки

```bash
python -m unittest tests.test_websites -v
python -m unittest discover -s tests -v
python -m tests.test_rules
docker build -t it-radar-bot:stage3 .
```

Добавлены 29 тестов сайтов: реальные шаблоны, фильтр опыта, полные описания,
более 15 деталей, многостраничная выдача, повторы/лимиты/неполный JSON,
отсутствующие даты, неверные ссылки, отказ доступа, изоляция ошибок и сохранение
старой очереди РТК ИТ без отправки. HTML/JSON в `tests/fixtures/websites/` сокращены
из публичных ответов; поля форм, стили и технические атрибуты удалены.

Для повторной реальной проверки из корня репозитория:

```bash
python -m scripts.probe_websites
python -m scripts.probe_websites --source k2_vacancy
# Либо с зависимостями из Docker:
docker run --rm -v "$PWD:/audit:ro" -w /audit it-radar-bot:stage3 python -m scripts.probe_websites
```

Диагностика не открывает SQLite и не отправляет сообщения. Возвращает код 1,
если хотя бы один источник недоступен; сейчас это ожидаемо для РТК ИТ. Реальные
токены не требуются. Код 0 означает успешный сбор всех выбранных источников,
а не подтверждение релевантности вакансий или открытости регистрации.
