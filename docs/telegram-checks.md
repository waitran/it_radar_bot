# Этап 2: публичные Telegram-каналы

Проверка 22 октября 2026 года, 03:25–03:28 МСК. Запросы выполнялись из Docker
с закреплёнными зависимостями, только к публичным `https://t.me/s/<username>`.
Токен бота, пользовательский аккаунт и MTProto не использовались. Уведомления
не отправлялись, рабочая SQLite не открывалась.

Дата выбирается из ссылки публикации, а не из первого `time` с длительностью

Обычные ссылки на каналы, посты и социальные сети не считаются регистрацией.
При нескольких равноценных ссылках единственное поле `apply_url` остаётся пустым.

Реальная догрузка `fetch_channel("rostelecom_tech", since_id=1886)` прочитала
две страницы и вернула 16 новых для этой границы публикаций. Вторая страница
позволила пересечь сохранённый ID. Отсутствующие ID допустимы: записи удаляются,
а альбомы не обязаны образовывать непрерывную последовательность.

Дополнительная проверка с `since_id=1880` вернула 21 запись с ID 1881–1906
с двух страниц, включая пять записей вне последней страницы. Первая попытка
получила `ConnectionError`, повторная завершилась успешно. Ошибка не была
представлена как пустая успешная выборка; рабочая БД в этих проверках не использовалась.

## Граница обработки и сохранность данных

- Первый успешный сбор нового канала читает только последнюю страницу и
  сохраняет её без рассылки архива, даже если `/start` уже был получен.
- Затем сборщик читает предыдущие страницы до ID не больше сохранённого либо
  до конца доступной истории. Возвращает записи старые → новые без повторов ID.
- По умолчанию допустимо 25 страниц за проверку. Лимит, ошибка сети, редирект,
  отсутствие даты, неожиданная пагинация или изменённый HTML дают явную ошибку.
  Частичный результат не возвращается; сохранённый ID не увеличивается.
- Граница записывается только после обработки полного набора. Незавершённый
  первый сбор остаётся исходной точкой после рестарта. Проверки записей в SQLite
  предотвращают повторную обработку уже сохранённой части набора.
- Используется существующая таблица `flags`: `telegram_cursor:tg_<username>`.
  Таблицы и старые записи не удаляются. При первом обновлении существующей БД
  берётся максимальный числовой ID из `seen_items` соответствующего канала.
  Публикации, ранее пропущенные старой версией до этого ID, автоматически
  восстановить нельзя.
- Ошибки источника отражаются под его ключом из `config.yaml` и очищаются после
  успешного чтения. Сбой одного канала не блокирует проверку следующего.

Лимит можно увеличить для отдельного канала в `config.yaml`:

```yaml
telegram_channels:
  - key: rostelecom_tech
    username: rostelecom_tech
    max_pages: 50
```

Это пример одного элемента; не заменяйте им весь список каналов.

## Повторение проверки

В подготовленном Python-окружении из корня репозитория:

```bash
python -m unittest tests.test_telegram -v
python -m scripts.probe_tg
python -m scripts.probe_tg --channel rostelecom_tech --since-id 1886
```

Команда тестов использует сохранённые примеры и подмену HTTP. Команды
`probe_tg` делают реальные публичные запросы, печатают только сводку и не создают
БД. Все семь каналов проверяются по умолчанию; канал должен быть в конфигурации.
Выйдут с кодом 1 при ошибке источника и 2 при ошибке настройки.

Если установка Python-зависимостей на хосте недоступна, используйте образ:

```bash
docker build -t it-radar-bot:stage2 .
docker run --rm -v "$PWD:/audit:ro" -w /audit it-radar-bot:stage2 python -m scripts.probe_tg
```

29 новых тестов покрывают все семь HTML-примеров, видео и текст, ссылки,
несколько страниц, удалённую границу, отсутствие новых постов, лимит, повтор
страницы, ошибки HTTP/сети/разметки, запрет переходов на посторонние URL,
перезапуск, сохранение старых записей и прерванную обработку. Вместе с этапом 1
и исходными тестами — 49 успешных проверок локально и в Docker-сборке.

`tests/fixtures/telegram/` содержит сокращённые публичные HTML-снимки:
сохранены структура сообщений, тексты, даты и ссылки; удалены аватары,
медиаресурсы, стили, счётчики и технические атрибуты просмотра.

## Границы этапа

Сбор сайтов, правила тематического отбора, дедлайны и повторы доставки здесь не
исправлялись. Не подтверждены качество отбора и работа бота целиком. Редактирование
старых постов с ID не выше сохранённой границы повторно не отслеживается. OCR,
прочтение регистрационных страниц и обход блокировок отсутствуют. Успешный сбор
сейчас не гарантирует дальнейшую доступность публичного веб-просмотра Telegram.
