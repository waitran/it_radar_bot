# Этап 4: отбор возможностей и сроки

Фильтр работает локально по тексту объявления и настройкам `rules`. Внешняя
модель, платный API и новые секреты не требуются. Это набор консервативных правил,
а не полное понимание произвольного текста: подходящая публикация без явных
признаков может быть пропущена.

## Правила

- Упоминания студентов, стажировок или конференций недостаточно. Нужны приглашение,
  подача заявки, распознанная будущая дата либо вакансия начального уровня.
- Включены стажировки, мероприятия, конкурсы и карьерные встречи. Требуется явный
  IT-контекст: например, Python, SOC, Linux, робототехника или информационные
  технологии. Само упоминание IT-компании не делает HR-вакансию технической.
- Сборщики К2 и КРОК помечают записи как вакансии; КРОК также передаёт теги опыта.
  Вакансии без признаков начального уровня, senior/middle/lead, руководящие роли
  и явно требующие от двух лет опыта отклоняются. Продажи, кадровое дело и
  финансовый документооборот исключаются из технических вакансий.
- Senior-спикер на митапе и опытный наставник стажёра сами по себе не исключают
  возможность. Явное ограничение аудитории опытными специалистами учитывается.
- Отчёты, записи мероприятий, рекламные розыгрыши и предложения покупки
  отсекаются. Обычные новости компании без приглашения не проходят.
- Явное закрытие регистрации/набора, прекращение приёма заявок и занятые места
  имеют приоритет. «Регистрация ещё не открыта» не становится статусом `open`.
- Проверяется полный текст, а не только обрезанная выдержка. Заголовок и краткое
  описание не дублируются при подсчёте ключевых слов.

## Настройки

В `config.yaml` доступны:

```yaml
rules:
  timezone: Europe/Moscow
  require_it_context: true
  min_score: 1
  max_age_days: 60
```

`categories` содержит включённые категории `internships`, `events`, `contests`,
`career`, их `label` и `keywords`. Чтобы отключить категорию, удалите её из этого
словаря. Пустой словарь отключает все категории. Можно добавлять свои ключевые
слова, например «техзавтрак» в `events`; требования актуальности и IT-контекста
продолжают действовать. Для вакансий используются также стандартные признаки
начального уровня и теги опыта.

`exclude_keywords` задаёт абсолютные пользовательские исключения. Совпадения
начинаются на границе слова: «акция» не совпадает с «транзакция». Русские окончания
поддерживаются через префиксы; отдельные английские слова сравниваются целиком.
`closed_words` дополняет встроенные признаки закрытия; не задавайте здесь слишком
широкие префиксы вроде «заверш», если не хотите исключать будущие завершения.

`require_it_context: false` разрешает нетехнические возможности, сохраняя
проверки начального уровня вакансий, закрытия и сроков. В конфигурации по умолчанию
эта настройка включена. Неизвестные категории, неправильный часовой пояс,
строковое значение вместо boolean и неверные числовые пороги дают явную ошибку.

## Сроки и статус

Распознаются `ДД.ММ.ГГГГ`, `ДД/ММ/ГГ`, `ГГГГ-ММ-ДД`, русские названия месяцев,
неполные даты и «сегодня/завтра/послезавтра» в контексте срока или мероприятия.
Время `ЧЧ:ММ` после даты учитывается. Дата без времени действует до конца дня
в настроенном часовом поясе. В уведомлении срок показывается со временем и зоной.

Год неполной даты берётся из даты публикации, а если её нет — из текущего года.
Истёкшая дата не переносится на следующий год. Относительная дата привязана
к публикации; без даты публикации она остаётся неизвестной. Версии программ
вроде Python 3.12 не считаются датами мероприятия.

При нескольких разных распознанных дедлайнах единственный срок не выбирается
произвольно. Если все прошли, запись отклоняется; если часть ещё впереди, статус
регистрации остаётся неизвестным. Структурированный дедлайн `JobPosting`,
полученный сборщиком, имеет приоритет над разбором текста.

Статус `open` ставится только при явном утверждении автора об открытии и одном
неистёкшем сроке. Сообщение сохраняет уточнение «по тексту объявления». Это не
проверка формы регистрации. Во всех остальных принятых случаях статус неизвестен.

Не интерпретируются произвольные формулировки вроде «в следующую пятницу», даты
в картинках и сложные условия нескольких программ внутри одного поста. Часовые
пояса в свободном тексте не переопределяют `rules.timezone`. Для даты без года
на стыке лет нужен явный год, иначе консервативное правило может пропустить анонс.

## Проверки

Все проверки воспроизводимы без сети и настоящих токенов:

```bash
python -m unittest tests.test_selection -v
python -m unittest discover -s tests -v
python -m tests.test_rules
docker build -t it-radar-bot:stage4 .
```

Добавлены 39 тестов, часть из них проверяет таблицы вариантов. В частности:
ошибки из аудита, категории и настройки, junior/senior, нетехнические вакансии,
граница московских суток, год публикации, относительные даты, неоднозначные
сроки, формат уведомления и повторная проверка истёкшего дедлайна.

Отдельно вручную размечены 13 примеров из сохранённых публичных снимков на
22 октября 2026 года, 12:00 МСК:

| Пример | Ожидаемое решение |
|---|---|
| МГТС `/16`, кейс-чемпионат «Код города» | Принять, срок 15 ноября 2026, статус неизвестен |
| КРОК `/2194`, дайджест стажировок | Принять |
| R-Vision `/1989`, набор технических стажёров | Принять |
| Ростелеком Tech `/1891`, `/1903`, Data & AI Talks 15–16 октября | Отклонить: событие прошло |
| Ростелеком Молодёжь `/889`, `/891`, `/895` | Отклонить: новости и отчёт |
| КРОК `/2179`, воспоминания о летней школе | Отклонить |
| ЦТДЛ `/670`, `/685`, голосование за работодателя и отчёт о конференции | Отклонить |
| К2 и КРОК, страницы стажёра-аналитика SOC | Принять, даты публикации неизвестны |

Это проверка конкретного набора примеров, а не измерение точности на всех будущих
публикациях. Старые два тестовых примера обновлены: для положительных случаев
лекции и карьерной встречи теперь явно указаны приглашение и IT-тематика.

## Что остаётся за пределами этапа

Рабочая БД не пересоздаётся и уже обработанные публикации автоматически не
переоцениваются. Новые поля типа вакансии/опыта используются при первичном отборе;
надёжное сохранение полного контекста очереди и её повторная проверка относятся
к этапу 5. Прежние проблемы повтора доставки, `/stop` во время отправки и
неоднозначного тайм-аута не решены этим этапом. Бот целиком ещё не прошёл приёмку.
