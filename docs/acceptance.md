владельца через Docker Compose. Бот: [@it_start_radar_bot](https://t.me/it_start_radar_bot).

Служебное тестовое сообщение не выдавалось за новую возможность. Отправку

Перед рабочим запуском также выполнен проход по реальным источникам в отдельной
тестовой SQLite без токена и с запретом отправки. Проверены отсутствие рассылки
и восстановление состояния после повторного открытия БД. Эта тестовая БД не
используется рабочим сервисом.

## Источники и ограничения

Все семь Telegram-каналов, К2 и КРОК прошли успешное чтение в рабочем сервисе.
Во время приёмки возникали временные ConnectionError/ConnectTimeout: ошибки
фиксировались отдельно, другие источники продолжали проверяться. К2, КРОК и
часть каналов восстановились при следующих проверках. Это не гарантия постоянной
доступности внешних сайтов; текущие ошибки видны через `/status` и в логах.

РТК ИТ остаётся неподключённым: публичный API отвечает HTTP 401. Авторизация и
обход доступа не выполняются; демонстрационные вакансии из JavaScript не используются.
Итого доступны 9 из 10 заданных источников, с учётом возможных временных сбоев сети.

Правила отбора консервативные: не распознают текст внутри изображений и не проверяют
работоспособность внешней формы регистрации. При неизвестном результате отправки
уведомление не повторяется автоматически — нужен разбор очереди по инструкции этапа 5.

## Рабочий режим

- Контейнер: `it-radar-bot`, сервис Compose: `it-radar-bot`.
- Уведомления включены; опрос источников примерно раз в час, согласно окружению.
- SQLite хранится в named volume `it_radar_bot_current_bot-data`.
- Политика перезапуска: `unless-stopped`.
- На корректное завершение процесса отведено 60 секунд вместо стандартного короткого
  тайм-аута: long polling и завершение текущего запроса могут требовать времени.
- Код размещён на GitHub, но исполняется локально. Компьютер и Docker должны работать;
  это не облачный хостинг. Отключённый/спящий компьютер не проверяет источники.

## Управление

Из корня репозитория:

```bash
# Состояние сервиса
docker compose ps

# Последние сообщения приложения
docker compose logs --tail 50 -f

# Остановить процесс, сохранив БД
docker compose stop

# Запустить снова
docker compose up -d

# После обновления кода
docker compose up -d --build
```

В Telegram `/stop` отключает уведомления, но сохраняет работающий мониторинг;
`/start` включает их обратно с новой исходной точкой после паузы. `/status`
показывает состояние источников и очереди. Не путайте это с остановкой контейнера.

Не используйте `docker compose down -v`, если нужно сохранить историю: `-v`
удаляет named volume. Не публикуйте вывод `docker inspect` или `docker compose config`
без `--quiet` — сторонние инструменты могут показывать переменные окружения.

Для неизвестных/старых доставок и восстановления см.
[инструкцию этапа 5](delivery-checks.md). Для изменения источников и правил
отредактируйте `config.yaml`, затем пересоберите/перезапустите сервис.
