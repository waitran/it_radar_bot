# it_radar_bot

Этапы 1–4 выполнены: запуск, публичные Telegram-страницы, сбор сайтов и фильтрация.
Полная готовность бота ещё не подтверждена: впереди надёжность доставки и приёмка. РТК ИТ сейчас не подключён из-за закрытого API.

## Описание сервиса

Сервис (`it-radar-bot`) — Telegram-бот, который автоматически отслеживает актуальные возможности для студентов и начинающих IT-специалистов в заданных источниках и присылает владельцу только новые подходящие публикации: стажировки и программы для начинающих, IT-мероприятия (митапы, конференции, лекции), хакатоны/соревнования/олимпиады/конкурсы, карьерные встречи. Обычные новости компаний и реклама продуктов отсекаются настраиваемыми правилами.

### Источники

**Telegram-каналы** читаются только через открытые веб-страницы `https://t.me/s/<username>` (без Telethon/Pyrogram/MTProto и без пользовательского аккаунта):
- t.me/rostelecom_tech
- t.me/rostelecom_molodezh
- t.me/CTDLru
- t.me/mgtsstudents
- t.me/brainzbycroc
- t.me/k2cybersec_team
- t.me/rvision_team

**Сайты компаний** (результат этапа 3):
- https://careers.cybersecurity.k2.tech/vacancy — публичный JSON-эндпоинт каталога Tilda (`app/collectors/k2.py`)
- https://careers.croc.ru/vacancies/?_sft_expirience=0-1-год — действующий фильтр `EXPERIENCE`, полный каталог и описания (`app/collectors/croc.py`)
- https://rtkit.ru/careers — не подключён: API возвращает 401, демоданные JavaScript не используются (`app/collectors/rtkit.py`)

### Категории отбора (настраиваются в `config.yaml`)

| Категория | Что ищет |
|---|---|
| `internships` | стажировки, программы для начинающих, junior/entry-level, практики |
| `events` | митапы, конференции, лекции, воркшопы, вебинары, дни открытых дверей |
| `contests` | хакатоны, соревнования, олимпиады, конкурсы, CTF, кейс-чемпионаты |
| `career` | карьерные встречи, ярмарки вакансий, дни карьеры, подработка для студентов |

Ключевые слова каждой категории, стоп-слова (новости/реклама), минимальный балл совпадений и максимальный возраст публикации задаются в секции `rules` файла `config.yaml`.

### Уведомления

- Присылаются **только новые подходящие публикации**: категория, компания/канал, краткое содержание, ссылка на оригинал и ссылка на регистрацию/заявку (если найдена).
- Явно закрытые объявления и публикации с истёкшим сроком подачи не отправляются.
- Если статус регистрации неизвестен, бот не утверждает, что она открыта.
- При первом запуске архив не рассылается: текущие публикации запоминаются как исходная точка (baseline).

### Механика работы

- Опрос источников примерно раз в час (`POLL_INTERVAL_SECONDS`, по умолчанию 3600) с разумной частотой запросов и паузами между источниками.
- Ошибка одного источника логируется и не останавливает остальные.
- Все ID и ссылки публикаций сохраняются в SQLite (`data/bot.db`) — дубли исключены при повторных проверках и перезапусках; одно объявление, опубликованное и в канале, и на сайте, не придёт дважды (дедупликация по нормализованному названию).
- Если источник недоступен для автоматического чтения, бот прямо сообщает об этом в логах и не пытается обойти ограничения.

### Команды бота

- `/start` — включить рассылку;
- `/stop` — выключить рассылку (новые объявления продолжают запоминаться, но не присылаются);
- `/status` — состояние источников и число сохранённых публикаций;
- `/help` — список команд.

Уведомления доставляются только владельцу, указанному в переменной окружения `OWNER_TELEGRAM_ID`. Сообщения от других пользователей игнорируются.

## Подготовка запуска (этап 1)

Этот этап проверяет установку, настройки и защиту логов. Он **не подтверждает
готовность сборщиков, фильтрации или доставки**: найденные аудитом ошибки этих
компонентов исправляются поэтапно. Результаты сбора приведены в отчётах этапов
2–3; это ещё не приёмка работающего бота.

### Секреты

Ранее опубликованный GitHub personal access token отзовите в GitHub Settings →
Developer settings → Personal access tokens. Для дальнейшей работы с приватным
репозиторием настройте новый токен локально через credential manager либо SSH.
GitHub-токен самому боту и Docker-сборке не требуется.

Telegram bot token, ранее записанный в старой копии `app/config.py`, отзовите
через @BotFather и получите новый. Не присылайте новые значения в чат, не
записывайте их в Python/YAML, команды с литералами или Git. Удаление старого
значения из файла не заменяет отзыв токена.

Создайте `.env` из `.env.example`, если файла ещё нет, ограничьте доступ и
заполните его локальным редактором:

```bash
cp -n .env.example .env
chmod 600 .env
```

Обязательны `TELEGRAM_BOT_TOKEN` и `OWNER_TELEGRAM_ID` (положительный числовой
Telegram ID владельца). Файл-шаблон намеренно содержит пустые значения.
`.env`, его варианты, базы данных и логи исключены из Git; Docker получает
только разрешённые исходники и не получает `.env` или историю Git в контексте сборки.

Compose читает `.env` автоматически и передаёт нужные переменные контейнеру.
Сам Python `.env` не читает: ему нужны экспортированные переменные окружения.
Значения из YAML не используются как учётные данные. Не включайте shell tracing
(`set -x`) при загрузке окружения и не публикуйте вывод `docker inspect` или
`docker compose config` без `--quiet`: инструменты Docker могут показывать окружение.

### Воспроизводимая установка

Целевое окружение — Python 3.12.12 на Debian Bookworm. Dockerfile фиксирует также
SHA-256 digest базового образа. `requirements.txt` содержит точные версии всех
прямых и транзитивных зависимостей. Подход описан в
[документации pip](https://pip.pypa.io/en/stable/topics/repeatable-installs/).

```bash
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip --isolated install --index-url https://pypi.org/simple --no-deps -r requirements.txt
python -m pip check
python -m tests.test_rules
python -m unittest discover -s tests -v
```

Тесты не требуют настоящих токенов. Тесты этапа 1 используют вымышленные значения,
подмену сети и временные файлы. Проверки правил запускаются отдельной командой,
поскольку они написаны как функции, а не `unittest.TestCase`.

Обновляйте зависимости отдельным изменением: в чистом Python 3.12 установите
нужные версии, сохраните полный `python -m pip freeze` в `requirements.txt`,
затем выполните `pip check`, оба набора тестов и Docker-сборку. Не обновляйте
зависимости автоматически при каждом запуске. Pinning не обеспечивает
доступность PyPI и не делает сборку побайтово идентичной.

### Проверка Docker без запуска мониторинга

```bash
docker build --progress=plain -t it-radar-bot:stage1 .
docker compose config --quiet
docker run --rm --network none --env-file .env it-radar-bot:stage1 python -m app.main --check-config
```

В процессе сборки выполняются `pip check`, шесть существующих тестов и проверки
этапов 1–4. При ошибке сборка прерывается. В финальный образ не копируются тесты и
секреты. Сборка не требует `.env`; проверка Compose требует заполненного файла.
`--check-config` проверяет формат настроек, но **не действительность токена**;
не обращается к Telegram, не опрашивает источники и не открывает SQLite.
Код возврата: 0 — настройки корректны, 2 — ошибка настроек.

### Локальная диагностика

Загрузите свой `.env` в окружение shell (для этой команды файл должен содержать
обычные shell-присваивания; значения с пробелами заключайте в кавычки):

```bash
set -a
. ./.env
set +a
python -m app.main --check-config
```

Логи приложения направлены в stderr. Форматтер маскирует настроенные через
окружение TOKEN/SECRET/PASSWORD/API_KEY, распознаваемые Telegram/GitHub-токены,
включая URL-кодирование, сообщения HTTP-библиотек и traceback. Токен исключён из
`repr(Config)`. Это защита вывода приложения, а не средство очистки старых логов,
истории Git, shell или вывода сторонних инструментов.

### Дальнейший рабочий запуск

После завершения следующих этапов:

```bash
docker compose up -d --build
docker compose logs -f
```

Для локального запуска создайте каталог `data`, задайте `DB_PATH=./data/bot.db`
(уже предусмотрено в `.env.example`) и используйте `python -m app.main`.
Compose задаёт `DB_PATH=/data/bot.db`; существующий named volume `bot-data`
сохраняется при пересборке. Не используйте `docker compose down -v`, если нужно
сохранить данные. На этапе 1 рабочий мониторинг автоматически не запускается.
